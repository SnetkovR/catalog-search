# План реализации

Цель: поиск ближайших фотографий по загруженному изображению, полностью на CPU.
Рабочее предположение: релевантность определяется товаром, а не накладной отправления.

## Этапы и отдельные коммиты

1. Каркас Python-пакета, зависимости и воспроизводимое окружение.
2. DINOv2 Small на CPU, безопасное чтение изображений, сохранение пропорций,
   необязательная область поиска, нормализация эмбеддингов.
3. Инкрементальная индексация папки, SQLite как постоянное хранилище,
   точный поиск NumPy, команды CLI. Изменения публикуются атомарно.
4. API загрузки, поиска, состояния и миниатюр; ограничение параллельного инференса.
5. Веб-интерфейс загрузки, выделения области и результатов.
6. Сквозная проверка на реальных примерах, замеры CPU, документация запуска.

Каждый этап проверяется до коммита. Исправления и дополнительные возможности
оформляются отдельными небольшими коммитами.

Все шесть этапов MVP реализованы. Результаты первой проверки и ограничения:
[docs/initial-evaluation.md](docs/initial-evaluation.md).

## Данные и ограничения MVP

- Исходные фотографии, модель, кеши и индекс не коммитятся.
- Модель: `facebook/dinov2-small`, Apache 2.0, 384-мерный CLS-эмбеддинг.
- Полный кадр вписывается в квадрат 224×224 с полями. Это сознательное отличие
  от центральной обрезки; его качество нужно оценивать на примерах пользователя.
- Область запроса выделяется вручную; автоматический детектор и OCR вне MVP.
- Полные кадры каталога пока индексируются без выделения товаров.
- На девяти примерах можно проверить работоспособность, но нельзя надежно
  оценить качество. Самосовпадение исключается в тестах поиска аналогов.
- Для одинаковых товаров с разными накладными полезна пара MIXIT
  `2026-09-26 15.11.52.jpg` / `2026-09-26 15.11.56.jpg`.
- Переход к ONNX/INT8/HNSW — после измерений, при подтвержденной необходимости.
- Проверка на macOS arm64 выявила конфликт OpenMP между установленными сборками
  PyTorch и FAISS. Для MVP используется точный поиск скалярным произведением
  нормализованных векторов в NumPy, без FAISS и обходных переменных OpenMP.

## Критерии готовности

Индекс сохраняется после перезапуска, повторная индексация пропускает неизмененные
файлы и убирает удаленные. Поврежденный файл не прерывает обработку каталога.
CLI и веб-интерфейс возвращают ранжированные результаты. Модель всегда работает
на CPU. Замеряется фактическая задержка, качество не выдается за гарантированное.
