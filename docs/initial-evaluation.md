# Первая проверка — 26 сентября 2026

Проверено на 9 изображениях из пользовательского `data/catalog`.
Фотографии, индекс, JSON-отчет и скриншоты хранятся локально и не коммитятся.

## Окружение и методика

- macOS 15.2, arm64; инференс только на CPU, 4 потока PyTorch.
- Python 3.12.14; PyTorch 2.14.0; Transformers 4.57.6; NumPy 2.5.3.
- DINOv2 Small, ревизия `ed25f3a31f01632728cabb09d1542f84ab7b0056`.
- FP32; EXIF → RGB → вписывание полного кадра 224×224 → CLS → L2-нормализация.
- Один прогрев, затем 9 запросов × 3 повторения, batch size 1.
- Полные файлы заранее прочитаны в память; измерены декодирование, подготовка,
  инференс и поиск. HTTP, чтение файлов и загрузка модели не входят в теплые замеры.
- При поиске исключены сам файл и все его побайтовые копии.

Команда:

```sh
.venv/bin/catalog-search --offline benchmark --repeats 3 --output var/benchmark.json
```

## Скорость

| Этап | Медиана, мс | p95, мс |
|---|---:|---:|
| Декодирование | 8,39 | 13,27 |
| Подготовка и эмбеддинг | 36,00 | 39,99 |
| Поиск по 9 векторам | 0,07 | 0,08 |
| Весь запрос без HTTP | 44,72 | 50,10 |

Загрузка энкодера из локального кеша: 2,175 с. Пиковая память процесса: около
500 МиБ. Первичная индексация 9 снимков: 0,574 с без загрузки модели.
В отдельной браузерной проверке API показал около 70 мс обработки загруженного
снимка. Это единичный пример, не нагрузочный тест.

Эти значения относятся к данному компьютеру и маленькому каталогу. Они не задают
SLA и не предсказывают скорость на другом CPU или на 100 000 фотографий.

## Наблюдения по выдаче

| Запрос | Наблюдение |
|---|---|
| MIXIT `15.11.52` / `15.11.56` | Вторая фотография набора на первом месте в обе стороны; сходство 0,874 |
| VOIS `15.12.13` / `15.12.21` | Разные продукты с похожим оформлением на первом месте друг у друга; сходство 0,849 |
| Набор ESTEL `15.12.10` | Отдельный пакет `15.12.17` на третьем месте, сходство 0,371 |
| Пакет ESTEL `15.12.17` | Фотография набора не попала в первую тройку |

Модель находит очевидную пару, но визуальное сходство упаковки и фона не означает
тождество товара. На девяти снимках нельзя надежно оценить качество. Для следующего
этапа нужны независимые фотографии запросов с разметкой релевантных товаров,
включая похожие упаковки разных артикулов и предметы внутри наборов. Затем стоит
сравнить полные кадры с областями товаров и проверить необходимость OCR.

## Проверка приложения

- 20 тестов обработки изображений, индекса и API пройдены.
- 2 сквозных теста Chromium пройдены: 1365×1000 и 390×844.
- Реальный снимок MIXIT загружен через веб-интерфейс; другая фотография набора
  проверена на первом месте. Ошибок JavaScript и горизонтального переполнения нет.
- Скриншоты просмотрены: `var/screenshots/search-desktop.png`,
  `var/screenshots/search-mobile.png`.
- Линтер и форматирование Python проверены.
